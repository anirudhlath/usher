# 07 — Client API

The contract every Usher client is built against. Nothing in this surface
mentions a media server; sources appear only as availability badges and
playback targets.

## Shape: hybrid, server-composed

**Screen-shaped endpoints** for paths that must be instant, **resource-shaped
endpoints** underneath for everything else.

**The server composes; the client renders.** `/home` returns ordered, hydrated
rows, and clients render them in order. Rows carry a display hint
(`portrait | landscape | wide | square`) but not a layout.

## Protocol

REST with an OpenAPI schema, generated by FastAPI. Clients codegen typed models
in any language. There is no GraphQL endpoint in v1.

## Endpoints

### Screens

| Endpoint | Returns |
|---|---|
| `GET /home` | Ordered, hydrated rows with reasons and display hints |
| `GET /search?q=&mode=&limit=` | Unified results across catalog and library |
| `GET /search/suggest?q=&tier=&limit=` | Type-ahead — the two tiers from [05](05-search-and-similarity.md), separately askable |
| `GET /browse?genre=&year=&sort=&owned=&facets=&cursor=` | Keyset paging; facet counts on request, for a predicated browse only |

**`GET /home`** composes server-side and carries no cursor. All ten row
providers are behind it, and a curated row arrives in the same envelope as the
other nine.

- A card carries `artwork` — one `images.id`, or `null`. **The id and nothing
  else**: never a URL and never a provider path. A client renders it by asking
  `GET /images/{id}`.
- **One id, chosen server-side against the row's own `display_hint`** — a
  poster for `portrait`/`square`, a backdrop for `landscape`/`wide`. A card is
  never handed a logo.
- **`null` means the catalog holds no image of that kind**, which is the
  ordinary state of a title nothing has derived yet.
- **`display_hint` is a hint and never a layout**, and reaches
  `/openapi.json` as an enum. No column count, no card width.
- **An empty database answers `200 {"rows": []}`** — not a 404, and not padded
  with a generic row. A synced library with no watch state is *not* empty.
- **The route never calls a source and never loads an embedding model.** Every
  input is local, so it cannot 503.
- **Answers a conditional request.** Every 200 carries a strong `sha256` `ETag`
  over the exact serialised bytes and `Cache-Control: private, max-age=30`. A
  repeat request carrying the `ETag` in `If-None-Match` gets `304` with no
  body, repeating both headers. `GET /titles/{id}` does not answer conditional
  requests.

**`GET /search`.** `?mode=` is the `SearchMode` enum — `full_text` (default),
`semantic`, `fused`; `?semantic=` is not accepted at all. The body carries
`query`, `requested_mode`, `mode`, `semantic_coverage`, `expanded_query` and
`results`.

- **`expanded_query` is present-and-null** rather than absent, unlike
  `GET /titles/{id}`'s absence convention.
- **A blank or whitespace-only `q` is `200` with no results and buys no
  completion.**
- **`?limit=` declares a floor and no ceiling**; the ceiling is
  `USHER_SEARCH_RESULT_LIMIT`.
- **`?mode=semantic` is served wherever this process holds an embedding model
  and answers `422 validation_failed` where it does not.** `?mode=fused`
  narrows to full text instead, and says so through `requested_mode` ≠ `mode`.
- ⚠️ **`semantic_coverage`'s denominator is the *enriched* tier, not the
  catalog.** It answers *"has the backfill drained?"*, not *"can the vector
  lane see this catalog?"* — on a catalog whose skeleton tier dwarfs its
  enriched one, `1.000` still means the semantic lane answers for a fraction of
  what the lexical one searches.

**`GET /search/suggest`.** `?tier=` is the `SuggestTier` enum, defaulting to
`prefix`; the response echoes the tier that answered and carries
`min_query_length`. The analytics row's household is the same singleton
`GET /search` uses, never a query parameter. Neither that read nor the row is
on the path the keystroke waits for, and `USHER_SEARCH_SUGGEST_ANALYTICS` ships
**on**.

**`GET /browse` facets are opt-in and predicated.** `?facets=true` plus at
least one of `genre`/`year`/`owned` is required, and each facet is counted over
the filtered population minus its own predicate. The response carries a
`computed` flag and *absent* rather than empty maps. A genre label from outside
Usher's vocabulary is mapped at read time.

### Resources

| Endpoint | Returns |
|---|---|
| `GET /titles/{id}?search_id=` | Detail: metadata, credits, images, availability, watch state. The optional, opaque `search_id` from a `GET /search` response records which result the household opened ([10](10-telemetry-and-dashboards.md)). Unknown, malformed or absent, it changes nothing and the resource is served identically |
| `GET /titles/{id}/similar` | Precomputed neighbours with similarity reasons |
| `GET /series/{id}/seasons` · `GET /seasons/{id}/episodes` | Series hierarchy |
| `GET /episodes/{id}` | Episode detail |
| `GET /people/{id}` | Filmography grouped by role |
| `GET /collections/{id}` | Franchise contents with ownership completeness |

**`GET /titles/{id}` renders credits as two keys**, `cast` and `crew`, each
capped at 20 and **absent when empty** — absent, never null and never `[]`.

**`images` is a list of ids and kinds**, filtered to those the image proxy
serves.

**`availability` is one badge per copy of the title, never per episode**, and a
copy carries no `external_id`.

**The route never calls a source.** Every field is local.

**`GET /people/{id}`** answers a person and their filmography as **groups**:
`cast`, plus one group per crew `job`, using the provider's own job strings. A
person credited twice on one title in two jobs appears in both groups.
`groups` is **absent rather than `[]`** when a person has no derived credits.
At most 50 credits are read — a bound of the route, not declared in the schema.

**`GET /collections/{id}`.** `owned` means an available, title-level media
item. A franchise the household owns none of is a `200` with `owned_count: 0`
rather than a 404. There is no cursor.

**`GET /series/{id}/seasons` and `GET /seasons/{id}/episodes` are separate
routes**, and neither carries `watch_state`. Season 0 is a season of the series
here, even though it is excluded from Next Up. An empty season list and an
empty episode page are `200`, not `404`.

### Actions

| Endpoint | Effect |
|---|---|
| `POST /titles/{id}/play?search_id=` · `POST /episodes/{id}/play?search_id=` | Resolve ranked `StreamTarget`s. The same optional, opaque `search_id` records that a result was played — only when a target was actually handed out, so a `409` and a `503` record nothing |
| `PUT /watch/titles/{id}` · `PUT /watch/episodes/{id}` | Set position / played |
| `POST /watch/titles/{id}/played` · `DELETE /watch/titles/{id}/played` | Mark played / unplayed |

**The watch write never reaches a source inside the request.** It writes
locally and enqueues a write-back job, so a failed push retries without
blocking the response. `watchstate.updated` is published for the client's own
write, so a second screen in the same household updates.

**`DELETE …/played` clears the played flag and nothing else** — not the
position, not the play count.

**Episodes get `PUT` and no `/played` pair.**

### Admin

| Endpoint | Purpose |
|---|---|
| `GET·POST /admin/sources` · `DELETE /admin/sources/{id}` | Configure sources |
| `GET /admin/sources/{id}/status` | Connection, push availability, last sync |
| `POST /admin/sources/{id}/sync` | Trigger reconcile |
| `GET /admin/unmatched` · `POST /admin/unmatched/{id}/resolve` | Review queue |
| `POST /admin/rows/regenerate` | Enqueue LLM curation for this household — 202, never a synchronous generate |
| `GET /admin/rows/providers` · `PUT /admin/rows/providers/{slug}` | Switch a row provider on or off |
| `GET /admin/bootstrap/status` · `POST /admin/bootstrap/{phase}` | Dataset import |

**`GET /admin/sources/{id}/status`** renders a `SourceStatus`, not a bool:
reachable, authenticated, `push_available` and `is_administrator` are each
three-valued where `null` means the check did not run
([03](03-sources-and-sync.md)).

**Every route that enqueues answers 202 with the job's key**, and the key is
`"{source id}:{lane}"` for a sync, the household id for a curation and the
phase for a bootstrap — a repeat press coalesces onto the same job rather than
queueing a second one. A 202 promises the job is queued and nothing about how
soon it runs: one worker lane is shared with every other queued kind
([08](08-operations.md)).

**`POST /admin/bootstrap/{phase}`** types `{phase}` as `BootstrapPhase`, so an
unknown phase is a 422 rather than a 404, and `all` and a single phase are two
keys and therefore two jobs.

**`GET /admin/bootstrap/status` answers 200 for every state** a database can be
in, including "no import has ever run". The genome vocabulary's verdict crosses
as a member rather than as a sentence.

**`GET /admin/rows/providers` answers one entry per registered provider**, with
`enabled` resolved from the operator's overrides — no override means enabled.
`PUT /admin/rows/providers/{slug}` takes `{"enabled": bool}`. Disabling a
provider makes the shelf disappear from every composer, and an operator may
disable everything and get an empty screen.

**`GET /admin/unmatched` pages by cursor, never by offset.** A queue entry
carries the source's own `external_id` — the one place a source concept is on
the wire.

**`POST /admin/unmatched/{id}/resolve` takes `{title_id, episode_id?}`** and
refuses an episode belonging to a different series before it writes. It
enqueues nothing and invalidates nothing.

**Every route in this table is unauthenticated**, like every other route here.

### Meta

| Endpoint | Purpose |
|---|---|
| `GET /health` · `GET /health/ready` | Liveness and readiness. `/health` carries `version`, the running package version; `/health/ready` does not, and its every field gates the status code |
| `GET /meta/attribution` | The four required attribution strings — IMDb, TMDb, MovieLens, Wikidata ([04](04-catalog-bootstrap.md)) |
| `GET /openapi.json` | Schema |

## Response contracts

### Enrichment state is always visible

Every title-bearing response carries `enrichment_state`
(`skeleton | stub | enriched`) so clients render deliberately — skeleton
shimmer on fields known to be missing — rather than inferring intent from
nulls. Whether the *last* enrichment attempt failed is a separate, independent
field, `enrichment_error`; this wire contract does not carry a `failed` tier.

```jsonc
{
  "id": "01936f2a-...",
  "name": "Dune",
  "year": 2021,
  "enrichment_state": "stub",     // overview not yet fetched
  "overview": null,
  // no "images", "cast" or "crew" key -- absent, never null and never [].
  "availability": [ { "source": "Emby", "quality": "2160p HDR10" } ],
  "watch_state": { "position_seconds": 1840, "played": false }
}
```

Requesting a `stub` promotes its enrichment job to the front of the queue
([03](03-sources-and-sync.md)) and returns immediately. The client is pushed
the filled-in version over SSE.

### DTOs are versioned independently

Wire types are distinct from Usher's internal models: internal refactors don't
break clients; wire changes are deliberate. Additive changes ship freely;
breaking changes get `/v2`.

### Pagination

Cursor-based (opaque, encodes sort position). Offset paging is not offered.

A paged response is `{"items": [...], "next_cursor": "…"}` — no `total`, and
`next_cursor` is `null` on the last page rather than absent. The cursor is
opaque: a client hands it back unread. It carries a **sort position and nothing
else** — no user, no grant, no offset — and is unsigned. A cursor that does not
match the query it is replayed against is a `400 invalid_cursor`.

Paging over a nullable sort key returns the null-keyed rows too; none is
dropped at a page boundary.

### Correlation: `traceresponse` on every response

Every response carries the id of the server span that produced it, in a W3C
Trace Context response header:

```
traceresponse: 00-0af7651916cd43dd8448eb211c80319c-b7ad6b7169203331-01
```

`version-traceid-spanid-flags`, lowercase hex, 2/32/16/2 characters. Usher
Console renders it as `Problem`'s "Open trace" link and carries it per journal
entry in the dev drawer ([10](10-telemetry-and-dashboards.md)).

- **A header, not a member of the problem envelope**, so it is present on a
  **200** too.
- **Absent, never zeroed.** A span that is not recording, and the all-zero
  span context, both emit no header at all.
- **A malformed header is `null` to a client, never a throw and never a partial
  id.**
- **No `Access-Control-Expose-Headers`; the console is same-origin.** A client
  on another origin cannot read the header until that list is added.

⚠️ **The one gap:** an unhandled exception answers Starlette's bare `500` from
outside the middleware that adds this, so that response carries no
`traceresponse`.

**On the name.** `traceresponse` is a *withdrawn draft* header; the published
Trace Context Level 2 Recommendation defines no response header.

### Errors

RFC 9457 problem details, with a machine-readable `code`:

```jsonc
{
  "type": "https://usher.dev/errors/source-unavailable",
  "title": "Source unavailable",
  "status": 503,
  "code": "source_unavailable",
  "detail": "Emby did not respond within 10s. Catalog data is served from cache.",
  "instance": "/titles/01936f2a-.../play"
}
```

The principle from [08](08-operations.md) holds at the boundary: a degraded
subsystem narrows functionality, it never fails a request local state can
answer.

#### The vocabulary

**Seven members, closed.**

| code | status | when |
|---|---|---|
| `not_found` | 404 | the addressed resource does not exist, on any route — and on any unrouted path |
| `validation_failed` | 422 | the request did not pass validation; the rejected fields ride in `errors`, never their values |
| `method_not_allowed` | 405 | raised by the router before any handler, so every route answers it |
| `invalid_cursor` | 400 | an opaque cursor that does not match the query it is replayed against |
| `source_unavailable` | 503 | at least one source could not be reached and nothing playable was found on the ones that answered — retryable |
| `not_playable` | 409 | every source holding a copy answered and none offers a way to play it |
| `ticket_invalid` | 404 | a playback ticket that is expired or forged — one answer for both, deliberately |

**404 is generic and there is no per-resource variant** — `instance` already
carries the path. A title the household owns with no playable copy is separated
by **status** (`409 not_playable`).

#### Stability

- **`code` is the machine-readable contract, and the status for a given code
  never changes.**
- **The set is closed at any instant and may grow additively within a major
  version**, so a client's `switch` on `code` needs a default arm — and that
  arm keys off `status`.
- **`title` and `detail` are prose and nothing may parse them.** Both may be
  reworded in any release. `detail` interpolates nothing a client submitted.

#### The shape

- **The media type is `application/problem+json`, on the wire and in
  `/openapi.json`.** It is how a client tells a problem document from a route's
  own body *before* parsing either.
- **`type` is derived from `code`** —
  `https://usher.dev/errors/<code-in-kebab-case>`. This project does not
  control `usher.dev`, so the URI is an identifier and is never dereferenced.
- **`status` always equals the response's HTTP status.**
- **`instance` is the request *path*, never the request URL**, so no query
  string is echoed back. A 422 for a malformed *path parameter* does carry that
  parameter; no credential is ever in a path in this API.
- **The 422 never echoes the submitted request body**, which may carry a source
  credential. The stripped `loc`/`msg`/`type`/`ctx` list rides as RFC 9457's
  `errors` extension member and `detail` is a fixed sentence.

**Two routes are exempt, by name:**

- **`GET /health/ready`** keeps `ReadinessResponse` for its 503, whose body
  says which check failed.
- **`GET /events`** keeps its in-stream vocabulary (`resync_required`) once
  `200 text/event-stream` has been sent. Its 422 for a malformed `?titles=` is
  decided before the stream starts and *is* a problem document.

Both exemptions are about what a **handler** answers; both routes still answer a
problem document for a 405.

A status with no member in the vocabulary is left in FastAPI's default shape
rather than given an invented code.

**A job-queue outage is an ordinary 500, never a 503**, on
`POST /admin/rows/regenerate` and on every route that writes. The vocabulary
holds no `queue_unavailable`, no `database_unavailable` and no
`internal_error`.

## Streaming updates (SSE)

`GET /events` — the channel that makes read-through visible to clients.

| Event | Payload | Client action |
|---|---|---|
| `title.updated` | Title id + changed fields | Patch in place |
| `watchstate.updated` | Title/episode id, position, played | Update progress |
| `row.invalidated` | Row slug | Refetch that row |
| `sync.progress` | Source, counts, phase | Admin UI only |
| `bootstrap.progress` | Phase, dataset, rows seen, rows written, cursor position | Admin UI only |

- Subscriptions are scoped by query (`?titles=id1,id2`).
- Reconnect sends `Last-Event-ID`; the server replays from a bounded buffer.
- **On buffer overflow the server emits `resync_required`** rather than
  silently skipping events.

**An event is a statement about committed state.** Every event is offered only
after **every write the unit of work that raised it made** has committed, not
merely the write the event is about — so a client that acts on a frame the
moment it arrives can read the change and everything that shipped with it. The
exceptions are the push lane and a reconcile's `sync.progress`, which each
commit their own subject before publishing.

**It is an ordering guarantee and not a delivery one.** The bus is in-process
and lossy: an event is lost when nobody is subscribed, when a subscriber's
buffer overflows, and when the process dies. `resync_required` and
`Last-Event-ID` answer every gap.

**Events raised by `usher work` running as a separate process reach no
subscriber**, so an enrichment finished there reaches a client only when it
refetches. The same applies to `bootstrap.progress` in a split deployment;
`GET /admin/bootstrap/status` is the durable record.

**`resync_required` is the channel's own event.** It answers a subscriber whose
buffer overflowed, a `Last-Event-ID` older than the replay ring, and one minted
by a previous process. An event id is `<epoch>-<n>`; the replay ring is
in-memory, so ids restart with the process under a new epoch.

**A stream's failure vocabulary is not the RFC 9457 envelope.** The five event
names plus `resync_required` are one closed enum, versioned independently, and
every member is emitted.

**The one ordinary HTTP failure**, `GET /events?titles=not-a-uuid`, is a `422`
naming the rule and never the submitted value. A malformed id fails the request
rather than being dropped from the filter.

**A heartbeat comment (`: keepalive`) is sent first and every
`USHER_SSE_HEARTBEAT_SECONDS` after**, default 20 s, bounded `< 60`. The
response also carries `Cache-Control: no-cache` and `X-Accel-Buffering: no`.

**`row.invalidated` is published by the push lane only**, one event per
invalidated slug over a small fixed set. The payload is a row slug, so the
`?titles=` filter cannot select it: it reaches unfiltered subscribers and no
others. Enrichment publishes none — `title.updated` already tells a client to
patch that card in place.

**A source's watch-state walk publishes nothing.** Its changes reach the screen
through the 30 s screen TTL and a demand read
([06](06-rows-and-recommendations.md)).

**`sync.progress` and `bootstrap.progress` are one frame per committed batch,
never one per run**, and never before that batch's own commit.
`bootstrap.progress` carries no percent: its cursor position is a
dataset-defined offset with no denominator — a byte offset for the IMDb dumps,
a page number for a SPARQL result set. It is scoped to no title, so no
`?titles=` subscription receives it.

## Images

`GET /images/{image_id}?w=` — the caching proxy from [02](02-data-model.md).
Fetches a provider **rung** on first request, stores the bytes on disk, and
serves them with immutable cache headers thereafter. It does not decode and
does not re-encode.

**`Cache-Control: public, max-age=31536000, immutable`** plus a strong `sha256`
`ETag` over the exact bytes served; a conditional request gets a `304` carrying
both. `public`, unlike every other cached route here: the bytes are identical
for every household, so a shared proxy may cache them. An image id survives a
re-derivation.

**The response names the rung it served** in `Content-Location`
(`/images/{id}?w=780`), built from the *clamped* rung, never from the request's
own path, so no byte a client sent reaches a response header.

**`w` is clamped up to a closed ladder of four widths** — `154 342 780 1280` —
with `342` when omitted and a 422 for anything that is not a positive integer.
There is no `original` rung.

**There is no `h=` and no `fmt=`**; artwork aspect ratio is fixed by kind.
Format negotiation over `Accept` is the named successor and is strictly
additive.

**Logos the provider stores as SVG are not served.**

**Six failures and each is a problem document.** A missing row is
`404 not_found`, and artwork this deployment declines to carry is the same
`404`: a client renders the fallback it renders for a title with no logo. A CDN
that did not answer, answered something unusable, asked to be backed off, or
refused this server's credentials is `503 source_unavailable` — with
`Retry-After` where there is one to send. Every route that can reach an
upstream answers the last two the same way.

Clients never see provider image URLs and never need a provider key.

## Playback

`POST /titles/{id}/play` and `POST /episodes/{id}/play` return ranked targets
rather than a single URL, and **every `url` is a ticket**:

```jsonc
{
  "targets": [
    {
      "kind": "direct",
      "url": "https://usher.example/stream/gAAAAABo…",
      "container": "mkv", "video_codec": "hevc", "hdr_format": "HDR10",
      "resolution": "3840x2160", "audio": "truehd_atmos_7_1",
      "runtime_seconds": 9360, "resume_position_seconds": 1840,
      "source": { "id": "…", "name": "Living Room Emby" }
    },
    {
      "kind": "deep_link", "scheme": "infuse",
      "url": "infuse://x-callback-url/play?url=https%3A%2F%2Fusher.example%2Fstream%2FgAAAAABo…",
      "source": { "id": "…", "name": "Living Room Emby" }
    }
  ]
}
```

The client chooses based on what it can play. Usher supplies complete
information and never proxies bytes.

`GET /stream/{ticket}` redeems a ticket into a **`302`** whose `Location` is
the real source URL, with `Cache-Control: no-store`. An expired or forged
ticket is a `404` — one answer for both, deliberately.

**`source` is per target, not per response.** A household with two copies of
one film has two sources and one list of targets ranked across both.

**`StreamTarget` carries `scheme`** (set only for `deep_link` targets, so a
client can check whether it handles the link without parsing the URL) and
**`audio`** (a single lowercase composite token, distinct from the raw
`audio_codec` a source reports). `kind` is a `StreamTargetKind` enum, not a
bare `str`.

**Three failures, each carrying a `code`:** a `404` for an id the catalog does
not hold; a `409 not_playable` when every source holding a copy answered and
none offers a way to play it; and a `503 source_unavailable` when at least one
source could not be reached and nothing playable was found on the ones that
could. A source that fails while *another* source answers is not a failure at
all — the playable targets are returned.

**The ticket** is an encrypted token under a subkey of `USHER_SECRET_KEY`, with
the source URL as its plaintext.

- **Encrypted rather than merely signed**: the plaintext URL carries the
  source's `api_key`.
- **Stateless** — no revocation before expiry; rotating `USHER_SECRET_KEY` is
  the coarse revocation that exists.
- **What it changes is the artifact, not the grant.** The `302`'s `Location` is
  the real URL, so the token still reaches the client that follows it; what
  stops being a working credential is what the client stores, renders, caches
  or pastes. The reduction is **weakest for the `deep_link` target**, which
  hands the ticket to a third-party player that then holds the real URL.
- **The TTL is five minutes**, a constant rather than a setting.

**The real source URL carries the source's session token**, and a client
receives it only as the `Location` of a `302` it followed on purpose. The token
is never logged, never a span attribute, and never persisted. It is held in
memory and re-minted only on a 401, so Usher applies no expiry of its own and
there is no rotation mechanism.

**The ticket URL inherits the request's own `Host`.** Behind a reverse proxy
that does not send `X-Forwarded-Proto`/`X-Forwarded-Host`, the ticket names the
internal address and the client follows a URL it cannot reach. The fix is an
operator setting (`uvicorn --proxy-headers`), not a code change
([08](08-operations.md)).

## Authentication seam

v1 has no authentication. Every request is served as the singleton default
user.

Adding real auth replaces that one seam; watch state, taste centroids and
curated rows are already keyed per user. Deploy behind your existing network
boundary until then.
