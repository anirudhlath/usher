# 07 — Client API

The contract every Usher client is built against. Nothing in this surface
mentions a media server; sources appear only as availability badges and
playback targets.

## Shape: hybrid, server-composed

**Screen-shaped endpoints** for paths that must be instant, **resource-shaped
endpoints** underneath for everything else.

Pure REST would make the home screen N+1 requests against a catalog that is
supposed to feel immediate. Pure BFF would couple the API to one client's
layout and defeat the purpose of building several.

**The server composes; the client renders.** `/home` returns ordered, hydrated
rows, and clients render them in order. Rows carry a display hint
(`portrait | landscape | wide | square`) but not a layout.

## Protocol

REST with an OpenAPI schema, generated by FastAPI. Clients codegen typed models
in any language.

GraphQL is deliberately *not* in v1 — screen-shaped endpoints already solve the
over-fetching problem it exists to fix, and REST stays simpler to cache, debug
and proxy. A Strawberry layer over the same services can be added if a client
turns out to need flexible field selection.

## Endpoints

### Screens

| Endpoint | Returns |
|---|---|
| `GET /home` | Ordered, hydrated rows with reasons and display hints |
| `GET /search?q=&mode=&limit=` | Unified results across catalog and library |
| `GET /search/suggest?q=&tier=&limit=` | Type-ahead — the two tiers from [05](05-search-and-similarity.md), separately askable |
| `GET /browse?genre=&year=&sort=&owned=&facets=&cursor=` | Keyset paging; facet counts on request, for a predicated browse only |

**`GET /home`** composes server-side and carries no cursor. All ten row
providers are behind it, and a curated row arrives in the same envelope as the
other nine.

- A card carries `artwork` — one `images.id`, or `null`. **The id and nothing
  else**: never a URL (which would bake this deployment's CDN base and ladder
  rung into a screen a client caches) and never a provider path. A client
  renders it by asking `GET /images/{id}`.
- **One id, chosen server-side against the row's own `display_hint`** — a
  poster for `portrait`/`square`, a backdrop for `landscape`/`wide`. The hint
  is a property of the *row*, one level above the card, so a client could not
  decide it. A card is never handed a logo.
- **`null` means the catalog holds no image of that kind**, which is the
  ordinary state of a title nothing has derived yet.
- **`display_hint` is a hint and never a layout**, and reaches
  `/openapi.json` as an enum. No column count, no card width.
- **An empty database answers `200 {"rows": []}`.** Not a 404 — a screen with
  nothing on it is a fact about the household — and deliberately not padded
  with a generic row, which would look personalised on a household that has
  watched nothing. A synced library with no watch state is *not* empty.
- **The route never calls a source and never loads an embedding model.** Every
  input is local, so it cannot 503.
- **Answers a conditional request.** Every 200 carries a strong `sha256` `ETag`
  over the exact serialised bytes and `Cache-Control: private, max-age=30` —
  `private`, because the screen is composed for one household. `max-age` is
  `services/home.py`'s own `_SCREEN_TTL`, restated rather than duplicated. A
  repeat request carrying the `ETag` in `If-None-Match` gets `304` with no
  body, repeating both headers. `GET /titles/{id}` does not adopt it, because
  opening an unenriched title promotes its job.

**`GET /search`.** `?mode=` is the `SearchMode` enum — `full_text` (default),
`semantic`, `fused`; `?semantic=` is not accepted at all. The body carries
`query`, `requested_mode`, `mode`, `semantic_coverage`, `expanded_query` and
`results`.

- **`expanded_query` is present-and-null** rather than absent, deliberately
  unlike `GET /titles/{id}`'s absence convention: an absent `images` is a fact
  about the *resource*, a null `expanded_query` is a fact about *this request*.
- **A blank or whitespace-only `q` is `200` with no results and buys no
  completion** — a search box sends one between keystrokes.
- **`?limit=` declares a floor and no ceiling**, because
  `USHER_SEARCH_RESULT_LIMIT` is the ceiling and spelling it twice is two
  numbers that agree until somebody moves one.
- **`?mode=semantic` is served wherever this process holds an embedding model
  and answers `422 validation_failed` where it does not.** `?mode=fused`
  narrows to full text instead, and says so through `requested_mode` ≠ `mode`.
- ⚠️ **`semantic_coverage`'s denominator is the *enriched* tier, not the
  catalog.** It answers *"has the backfill drained?"*, not *"can the vector
  lane see this catalog?"* — on a catalog whose skeleton tier dwarfs its
  enriched one, `1.000` still means the semantic lane answers for a fraction of
  what the lexical one searches.

**`GET /search/suggest`.** `?tier=` is the `SuggestTier` enum, defaulting to
`prefix`; the response echoes the tier that answered and carries
`min_query_length`. A household id is resolved for the analytics row from the
same singleton `GET /search` uses and never from a query parameter. Neither the
household read nor the row is on the path the keystroke waits for: the read is
deferred into the handler and the row is appended to an in-process buffer
written by a drain, which is why `USHER_SEARCH_SUGGEST_ANALYTICS` ships **on**.

**`GET /browse` facets are opt-in and predicated.** A predicate does not make
them affordable, because each facet is computed over the filtered population
minus its own predicate. `?facets=true` plus at least one of
`genre`/`year`/`owned` is required; the response carries a `computed` flag and
*absent* rather than empty maps. A genre label from outside Usher's vocabulary
is mapped at read time.

### Resources

| Endpoint | Returns |
|---|---|
| `GET /titles/{id}?search_id=` | Detail: metadata, credits, images, availability, watch state. The optional, opaque `search_id` from a `GET /search` response records which result the household opened ([10](10-telemetry-and-dashboards.md)). Unknown, malformed or absent, it changes nothing and the resource is served identically |
| `GET /titles/{id}/similar` | Precomputed neighbours with similarity reasons |
| `GET /series/{id}/seasons` · `GET /seasons/{id}/episodes` | Series hierarchy |
| `GET /episodes/{id}` | Episode detail |
| `GET /people/{id}` | Filmography grouped by role |
| `GET /collections/{id}` | Franchise contents with ownership completeness |

**`GET /titles/{id}` renders credits as two keys**, `cast` and `crew`, each
capped at 20 and **absent when empty** — absent, never null and never `[]`.

**`images` is a list of ids and kinds**, filtered by
`usher.ports.images.is_servable_path`.

**`availability` is one badge per copy of the title, never per episode**, and a
copy carries no `external_id`: a source's own item id is a source concept.

**The route never calls a source.** Every field is local.

**`GET /people/{id}`** answers a person and their filmography as **groups**:
`cast`, plus one group per crew `job`, using the provider's own job strings. A
person credited twice on one title in two jobs appears in both groups.
`groups` is **absent rather than `[]`** when a person has no derived credits.
At most 50 credits are read, which is the route's bound rather than the
schema's.

**`GET /collections/{id}`.** `owned` means an available, title-level media
item. A franchise the household owns none of is a `200` with `owned_count: 0`
rather than a 404. There is no cursor: TMDb franchises are single-digit to
low-double-digit, which is stated as a bound.

**`GET /series/{id}/seasons` and `GET /seasons/{id}/episodes` stay separate
routes**, and neither carries `watch_state`. Season 0 is a season of the series
here, even though it is excluded from Next Up. An empty season list and an
empty episode page are `200`, not `404`.

### Actions

| Endpoint | Effect |
|---|---|
| `POST /titles/{id}/play?search_id=` · `POST /episodes/{id}/play?search_id=` | Resolve ranked `StreamTarget`s. The same optional, opaque `search_id` records that a result was played — only when a target was actually handed out, so a `409` and a `503` record nothing |
| `PUT /watch/titles/{id}` · `PUT /watch/episodes/{id}` | Set position / played |
| `POST /watch/titles/{id}/played` · `DELETE /watch/titles/{id}/played` | Mark played / unplayed |

**The watch write never reaches a source inside the request.** It writes
locally at `origin = api` and enqueues a write-back job at `VISIBLE` priority,
so a failed push retries without blocking the response.
`watchstate.updated` is published for the client's own write, so a second
screen in the same household updates.

**`DELETE …/played` clears the played flag and nothing else** — not the
position, not the play count.

**Episodes get `PUT` and no `/played` pair**, which is the table read
literally.

### Admin

| Endpoint | Purpose |
|---|---|
| `GET·POST /admin/sources` · `DELETE /admin/sources/{id}` | Configure sources |
| `GET /admin/sources/{id}/status` | Connection, push availability, last sync |
| `POST /admin/sources/{id}/sync` | Trigger reconcile |
| `GET /admin/unmatched` · `POST /admin/unmatched/{id}/resolve` | Review queue |
| `POST /admin/rows/regenerate` | Enqueue LLM curation for this household — 202, never a synchronous generate |
| `GET /admin/rows/providers` · `PUT /admin/rows/providers/{slug}` | Switch a row provider on or off — the registry left-joined onto `row_provider_settings`, so there is an entry per registered provider and absence means enabled |
| `GET /admin/bootstrap/status` · `POST /admin/bootstrap/{phase}` | Dataset import |

**`GET /admin/sources/{id}/status`** renders a `SourceStatus`, not a bool:
reachable, authenticated, `push_available` and `is_administrator` are each
three-valued where `null` means the check did not run
([03](03-sources-and-sync.md)).

**Every route that enqueues answers 202 with the job's key**, and the key is
`"{source id}:{lane}"` for a sync, the household id for a curation and the
phase for a bootstrap — `(kind, key)` is unique, so a repeat press coalesces
onto one row rather than queueing a second walk. A 202 promises the row is
queued and nothing about how soon it runs: one worker lane is shared with every
other queued kind, and head-of-line blocking is a real cost of the design
([08](08-operations.md)).

**`POST /admin/bootstrap/{phase}`** types `{phase}` as `BootstrapPhase`, so an
unknown phase is a 422 rather than a 404, and `all` and a single phase are two
keys and therefore two jobs.

**`GET /admin/bootstrap/status` answers 200 for every state** a database can be
in, including "no import has ever run". The genome vocabulary's verdict crosses
as a member rather than as a sentence.

**`GET /admin/rows/providers` answers the registry, not the table** — one entry
per registered provider, with `enabled` resolved from the overrides.
`PUT /admin/rows/providers/{slug}` takes `{"enabled": bool}`. Disabling a
provider makes the shelf disappear from every composer, and an operator may
disable everything and get an empty screen.

**`GET /admin/unmatched` pages by cursor, never by offset**, because the sort
key is nullable and a page boundary lands inside the undated group. A queue
entry carries the source's own `external_id`, which is the one place a source
concept is deliberately on the wire — an operator resolving a queue entry is
looking at their media server.

**`POST /admin/unmatched/{id}/resolve` takes `{title_id, episode_id?}`** and
refuses an episode belonging to a different series before it writes. It
enqueues nothing and invalidates nothing.

**Every route in this table is unauthenticated**, like every other route here.

### Meta

| Endpoint | Purpose |
|---|---|
| `GET /health` · `GET /health/ready` | Liveness and readiness. `/health` carries `version`, the running package version — additive, and deliberately not on `/health/ready`, whose every field gates the status code |
| `GET /meta/attribution` | The four required attribution strings — IMDb, TMDb, MovieLens, Wikidata ([04](04-catalog-bootstrap.md)) |
| `GET /openapi.json` | Schema |

## Response contracts

### Enrichment state is always visible

Every title-bearing response carries `enrichment_state`
(`skeleton | stub | enriched`) so clients render deliberately — skeleton
shimmer on fields known to be missing — rather than inferring intent from
nulls. Whether the *last* enrichment attempt failed is a separate, independent
field, `enrichment_error`; this wire contract does not carry a `failed` tier.

```jsonc
{
  "id": "01936f2a-...",
  "name": "Dune",
  "year": 2021,
  "enrichment_state": "stub",     // overview not yet fetched
  "overview": null,
  // no "images", "cast" or "crew" key -- absent, never null and never [].
  "availability": [ { "source": "Emby", "quality": "2160p HDR10" } ],
  "watch_state": { "position_seconds": 1840, "played": false }
}
```

Requesting a `stub` promotes its enrichment job to the front of the queue
([03](03-sources-and-sync.md)) and returns immediately. The client is pushed
the filled-in version over SSE.

### DTOs are versioned independently

`api/dto/` types are distinct from `domain/` models. Internal refactors don't
break clients; wire changes are deliberate. Additive changes ship freely;
breaking changes get `/v2`.

### Pagination

Cursor-based (opaque, encodes sort position). Offset paging is not offered — it
degrades badly over a 1.3M-row catalog and produces duplicates under concurrent
writes.

A paged response is `{"items": [...], "next_cursor": "…"}` — no `total`, and
`next_cursor` is `null` on the last page rather than absent. The cursor is
opaque: a client hands it back unread. It carries a **sort position and nothing
else** — no user, no grant, no offset — which is why it is unsigned, and **no
port ever takes one**; repositories take typed keyset values. A cursor that
does not match the query it is replayed against is a `400 invalid_cursor`.

The keyset predicate has **three arms**, because a row comparison over a
nullable key evaluates to **NULL, not false**, when the first differing pair
involves one — which silently drops the whole unkeyed tail with every page
still full.

### Correlation: `traceresponse` on every response

Every response carries the id of the server span that produced it, in a W3C
Trace Context response header:

```
traceresponse: 00-0af7651916cd43dd8448eb211c80319c-b7ad6b7169203331-01
```

`version-traceid-spanid-flags`, lowercase hex, 2/32/16/2 characters. Usher
Console renders it as `Problem`'s "Open trace" link and carries it per journal
entry in the dev drawer ([10](10-telemetry-and-dashboards.md)).

- **A header, not a member of the problem envelope.** `ProblemResponse` is a
  closed contract a generated client's types derive from, and a trace id is not
  part of what went wrong. The header is also the only spelling available on a
  **200**.
- **Absent, never zeroed.** A span that is not recording, and the all-zero
  `INVALID_SPAN`, both emit no header at all: that value is well-formed to
  every regex, names a trace nobody can open, and is forbidden by the grammar.
- **A malformed header is `null` to a client, never a throw and never a partial
  id.**
- **No `Access-Control-Expose-Headers`, because the console is same-origin.** A
  future client on another origin needs that list adding.

⚠️ **The one gap:** an unhandled exception answers Starlette's bare `500` from
outside the middleware that adds this, so that response carries no
`traceresponse`.

**On the name.** `traceresponse` is a *withdrawn draft* header; the published
Trace Context Level 2 Recommendation defines no response header, and the
current draft carries this grammar on a `Server-Timing` metric named `trace`.
The value is unchanged between them, and `traceresponse` is what the
OpenTelemetry ecosystem already emits.

### Errors

RFC 9457 problem details, with a machine-readable `code`:

```jsonc
{
  "type": "https://usher.dev/errors/source-unavailable",
  "title": "Source unavailable",
  "status": 503,
  "code": "source_unavailable",
  "detail": "Emby did not respond within 10s. Catalog data is served from cache.",
  "instance": "/titles/01936f2a-.../play"
}
```

The principle from [08](08-operations.md) holds at the boundary: a degraded
subsystem narrows functionality, it never fails a request local state can
answer.

#### The vocabulary

**Seven members, closed.** `tests/unit/test_api_problem_vocabulary.py` compares
this vocabulary to `ProblemCode` in both directions, so a route that needs a
code the design did not give it amends the decision in the same commit.

| code | status | when |
|---|---|---|
| `not_found` | 404 | the addressed resource does not exist, on any route — and on any unrouted path |
| `validation_failed` | 422 | the request did not pass validation; the rejected fields ride in `errors`, never their values |
| `method_not_allowed` | 405 | raised by the router before any handler, so every route answers it |
| `invalid_cursor` | 400 | an opaque cursor that does not match the query it is replayed against |
| `source_unavailable` | 503 | at least one source could not be reached and nothing playable was found on the ones that answered — retryable |
| `not_playable` | 409 | every source holding a copy answered and none offers a way to play it |
| `ticket_invalid` | 404 | a playback ticket that is expired or forged — one answer for both, deliberately |

**404 is generic and there is no per-resource variant.** `instance` already
carries the path, a per-resource member grows the vocabulary linearly with the
resource count, and every one is handled identically by a client. The one case
that could have justified a second 404 — a title the household owns with no
playable copy — is separated by **status** (`409 not_playable`).

#### Stability

- **`code` is the machine-readable contract, and the status for a given code
  never changes.** A code meaning 404 on one route and 409 on another would be
  two codes wearing one name.
- **The set is closed at any instant and may grow additively within a major
  version**, so a client's `switch` on `code` needs a default arm — and that
  arm keys off `status`, which the previous rule makes safe.
- **`title` and `detail` are prose and nothing may parse them.** Both may be
  reworded in any release. `detail` interpolates nothing a client submitted.

#### The shape

- **The media type is `application/problem+json`, on the wire and in
  `/openapi.json`.** It is how a client tells a problem document from a route's
  own body *before* parsing either. Both halves are pinned: `api/errors.py`
  sets it on the response, and `UsherAPI.openapi` moves every
  `ProblemResponse` declaration onto it in a post-pass, because FastAPI renders
  an additional response's model under the route's media type.
- **`type` is derived from `code` by one function** —
  `https://usher.dev/errors/<code-in-kebab-case>` — so a code and its type
  cannot drift apart. This project does not control `usher.dev`, so the URI is
  an identifier deliberately never dereferenced.
- **`status` is written once.** The handler builds the document and then builds
  the response *from* `document.status`.
- **`instance` is the request *path*, never the request URL.** A rejected `?q=`
  echoed back would be the same leak the 422 handler exists to prevent. A 422
  for a malformed *path parameter* does carry that parameter, which is inherent
  to RFC 9457; no credential is ever in a path in this API.
- **The 422 never echoes the submitted request body**, because that body
  carries a source credential. The stripped `loc`/`msg`/`type`/`ctx` list rides
  as RFC 9457's `errors` extension member and `detail` is a fixed sentence.

**Two routes are exempt, by name, with their reasons recorded in code** — as a
mapping in `dto/problem.py` that the "every route declares its problem
responses" check imports rather than re-derives:

- **`GET /health/ready`** keeps `ReadinessResponse` for its 503. Its real
  consumers gate on the status code and never parse the body, and the body says
  which check failed, which a `code` would not.
- **`GET /events`** keeps its in-stream vocabulary (`resync_required`): RFC
  9457 formats a response body, and after `200 text/event-stream` there is no
  status code left to carry one. Its 422 for a malformed `?titles=` is decided
  before the stream starts and *is* a problem document.

Both exemptions are about what a **handler** answers; a 405 is raised by the
router before any handler runs, so every route answers a problem document for
one. The exemption set is closed over `create_app()`'s own route table.

A status with no member in the vocabulary is left in FastAPI's default shape
rather than given an invented code. `_CODE_FOR_STATUS` covers only the three
statuses raised by machinery Usher does not control; every status Usher's own
code raises names its code at the raise site.

**The queue-outage rule binds every future route that writes.**
`POST /admin/rows/regenerate` answers an ordinary 500 when the job queue is
unreachable, because a 503 there would say *"this endpoint is degraded, retry
it"* about a deployment in which every endpoint is down. The vocabulary
therefore holds no `queue_unavailable`, no `database_unavailable` and no
`internal_error`.

## Streaming updates (SSE)

`GET /events` — the channel that makes read-through visible to clients.

| Event | Payload | Client action |
|---|---|---|
| `title.updated` | Title id + changed fields | Patch in place |
| `watchstate.updated` | Title/episode id, position, played | Update progress |
| `row.invalidated` | Row slug | Refetch that row |
| `sync.progress` | Source, counts, phase | Admin UI only |
| `bootstrap.progress` | Phase, dataset, rows seen, rows written, cursor position | Admin UI only |

- Subscriptions are scoped by query (`?titles=id1,id2`) so a detail screen is
  not woken by unrelated churn.
- Reconnect sends `Last-Event-ID`; the server replays from a bounded buffer.
- **On buffer overflow the server emits `resync_required`** rather than
  silently skipping events.

SSE over WebSocket because the channel is server→client only, it survives
proxies that mangle upgrades, and it reconnects natively in browsers.

**An event is a statement about committed state.** Every event is offered only
after **every write the unit of work that raised it made** has committed, not
merely the write the event is about — so a client that acts on a frame the
moment it arrives can read the change and everything that shipped with it. That
is structural for jobs, whose transaction closes above the service, and
deliberately not for the lanes: the push lane and a reconcile's `sync.progress`
each commit their own subject before publishing, and a progress event held
behind a whole walk would arrive as one jump at the end.

**It is an ordering guarantee and not a delivery one.** The bus is in-process
and lossy by design: an event is lost when nobody is subscribed, when a
subscriber's buffer overflows, and when the process dies. `resync_required` and
`Last-Event-ID` answer every gap.

**`usher work` as a separate process publishes to `NullEventPublisher`**, so an
enrichment finished in another process reaches no subscriber. A client that
refetches still gets the enriched title — degradation rather than breakage —
and the fix is a second implementation of the port rather than a branch in a
service. The same applies to `bootstrap.progress` in a split deployment;
`import_runs` and `GET /admin/bootstrap/status` are the durable record.

**`resync_required` is the channel's own event.** It answers a subscriber whose
buffer overflowed, a `Last-Event-ID` older than the replay ring, and one minted
by a previous process — the ring is in-memory, so ids restart with it and the
id a client sees is `<epoch>-<n>`. Without the epoch the third is undetectable.

**A stream's failure vocabulary is not the RFC 9457 envelope.** The four event
names plus `resync_required` are pinned as a `StrEnum` in `api/dto/events.py`,
versioned independently, with no member nothing emits.

**The one ordinary HTTP failure**, `GET /events?titles=not-a-uuid`, is a `422`
naming the rule and never the submitted value. A malformed id is rejected
rather than dropped: a filter built from the half that parsed is *narrower*
than the client asked for, so a detail screen would silently never update.

**A heartbeat comment (`: keepalive`) is sent first and every
`USHER_SSE_HEARTBEAT_SECONDS` after**, default 20 s, bounded `< 60` by the
type, because proxies close idle connections and an SSE stream on a quiet
library sends nothing for hours. The response also carries
`Cache-Control: no-cache` and `X-Accel-Buffering: no`.

**`row.invalidated` is published by the push lane only**, one event per
invalidated slug over a small fixed set. The `?titles=` filter cannot express
it and does not need to: the payload is a row slug, so it reaches unfiltered
subscribers and no others. `EnrichService` publishes none — `title.updated`
already tells a client to patch that card in place.

**The nightly walk publishes nothing**, deliberately: it merges up to a million
states, and one event per merged row is a fan-out per row per night to every
connected client. Its changes reach the screen through the 30 s screen TTL and
a demand read ([06](06-rows-and-recommendations.md)).

**`sync.progress` and `bootstrap.progress` are one frame per committed batch,
never one per run**, and never before that batch's own commit.
`bootstrap.progress` carries no percent, because a `BulkCursor`'s `position` is
a dataset-defined offset with no denominator — a byte offset for the IMDb
dumps, a page number for a SPARQL result set that has no total. It is scoped to
no title, which is what makes "Admin UI only" a property rather than a
convention.

## Images

`GET /images/{image_id}?w=` — the caching proxy from [02](02-data-model.md).
Fetches a provider **rung** on first request, stores the bytes on disk, and
serves them with immutable cache headers thereafter. It does not decode and
does not re-encode.

**`Cache-Control: public, max-age=31536000, immutable`** plus a strong `sha256`
`ETag` over the exact bytes served; a conditional request gets a `304` carrying
both. `public`, unlike every other cached route here: an image takes no user
and the bytes are identical for every household, so a shared proxy caching them
is the feature rather than a leak. `immutable` is earned by
`uq_images_owner_provider_path`, which makes an image id survive a
re-derivation.

**The response names the rung it served** in `Content-Location`
(`/images/{id}?w=780`), built from the route table and the *clamped* rung,
never from the request's own path, so no byte a client sent reaches a response
header.

**`w` is clamped up to a closed ladder of four widths** — `154 342 780 1280`, a
code constant — with `342` when omitted and a 422 for anything that is not a
positive integer. There is no `original` rung: it is the one size with no width
bound at all, and serving it is the disk-and-bandwidth hazard the clamp exists
to prevent. The provider's own CDN enforces its own allowlist, so the ladder
bounds *Usher's* disk cache at four entries per image and keeps Usher's API off
a provider's vocabulary.

**There is no `h=` and no `fmt=`.** The provider publishes one height rung, for
a kind Usher does not emit, and artwork aspect ratio is fixed by kind; and the
provider negotiates format on `Accept`, not on a query string. Format
negotiation over `Accept` is the named successor and is strictly additive.

**Logos the provider stores as SVG are not served.** The CDN ignores the ladder
for `image/svg+xml`, so nothing the clamp does can bound one, and the proxy
will not store active content under a year-long `max-age`.

**Six failures and each is a problem document.** A missing row is
`404 not_found`, and artwork this deployment declines to carry is the same
`404`, because a client owes it the same fallback it renders for a title with
no logo. A CDN that did not answer, answered something unusable, asked to be
backed off, or refused this server's credentials is `503 source_unavailable` —
with `Retry-After` where there is one to send. The last two are answered by an
exception handler on the app rather than by this route, so every route that can
reach an upstream gets them.

Clients never see provider image URLs and never need a provider key.

## Playback

`POST /titles/{id}/play` and `POST /episodes/{id}/play` return ranked targets
rather than a single URL, and **every `url` is a ticket**:

```jsonc
{
  "targets": [
    {
      "kind": "direct",
      "url": "https://usher.example/stream/gAAAAABo…",
      "container": "mkv", "video_codec": "hevc", "hdr_format": "HDR10",
      "resolution": "3840x2160", "audio": "truehd_atmos_7_1",
      "runtime_seconds": 9360, "resume_position_seconds": 1840,
      "source": { "id": "…", "name": "Living Room Emby" }
    },
    {
      "kind": "deep_link", "scheme": "infuse",
      "url": "infuse://x-callback-url/play?url=https%3A%2F%2Fusher.example%2Fstream%2FgAAAAABo…",
      "source": { "id": "…", "name": "Living Room Emby" }
    }
  ]
}
```

The client chooses based on what it can play. Usher supplies complete
information and never proxies bytes.

`GET /stream/{ticket}` redeems a ticket into a **`302`** whose `Location` is
the real source URL, with `Cache-Control: no-store`. An expired or forged
ticket is a `404` — one answer for both, deliberately.

**`source` is per target, not per response.** A household with two copies of
one film has two sources and one list of targets ranked across both.

**`StreamTarget` carries `scheme`** (set only for `deep_link` targets, so a
client can check whether it handles the link without parsing the URL) and
**`audio`** (a single lowercase composite token, distinct from the raw
`audio_codec` a source reports). `kind` is a `StreamTargetKind` enum, not a
bare `str`.

**Three failures, each carrying a `code`:** a `404` for an id the catalog does
not hold; a `409 not_playable` when every source holding a copy answered and
none offers a way to play it; and a `503 source_unavailable` when at least one
source could not be reached and nothing playable was found on the ones that
could. A source that fails while *another* source answers is not a failure at
all — the playable targets are returned.

**The ticket.** A Fernet token over an HKDF-SHA256 subkey of
`USHER_SECRET_KEY`, domain-separated from the source-credential subkey, with
the source URL as its plaintext.

- **Encrypted rather than merely signed**, because the payload *is* the URL
  carrying `api_key`: a signed-but-readable token would publish the credential
  it exists to hide.
- **Stateless** — there is no ticket table, so no revocation before expiry;
  rotating `USHER_SECRET_KEY` is the coarse revocation that exists.
- **Expired and forged are deliberately indistinguishable**, and redemption
  raises nothing rather than building an error message a URL could leak into.
- **What it changes is the artifact, not the grant.** The `302`'s `Location` is
  the real URL, so the token still reaches the client that follows it; what
  stops being a working credential is what the client stores, renders, caches
  or pastes. The reduction is **weakest for the `deep_link` target**, which
  hands the ticket to a third-party player that then holds the real URL.
- **The TTL is a named constant at the one place that mints**, not a setting:
  `usher.api.routers.playback.TICKET_TTL_SECONDS`, five minutes — long enough
  for the slowest legitimate hand-off, short enough that a stored or pasted URL
  stays useful for minutes rather than the hours a source token lives.

**The port DTO below the route still carries the source's session token in
`url`**, because a URL without one is a URL that does not play; Emby
authenticates its stream route and neither a `<video>` element nor a deep link
can set a header. `usher.services.playback` substitutes a ticket for every
`url` before the response DTO is built, so the token reaches a client only as
the `Location` of a `302` it followed on purpose. The token is never logged —
enforced once on the DTO that carries it — never a span attribute, and never
persisted. It is held in memory for the adapter's lifetime and re-minted only
on a 401, so Usher applies no expiry of its own and there is no rotation
mechanism.

**The ticket URL is built with `request.url_for`, so it inherits the request's
own `Host`.** Behind a reverse proxy that does not send
`X-Forwarded-Proto`/`X-Forwarded-Host`, the ticket names the internal address
and the client follows a URL it cannot reach. The fix is an operator setting
(`uvicorn --proxy-headers`), not a code change ([08](08-operations.md)).

## Authentication seam

v1 has no authentication. Every route depends on `current_user`, which returns
the singleton default user.

Adding real auth replaces that one dependency. Watch state, taste centroids and
curated rows are already keyed per user, so nothing else moves. Deploy behind
your existing network boundary until then.
